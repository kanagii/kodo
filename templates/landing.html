the actual problem

You can write it and still not really get it.

Most visualizers show bubble sort or BFS on a demo array that isn't yours. That's fine until you're debugging your own recursion or explaining your own pointer logic in an interview — and it turns out you never actually watched it happen.

other visualizers

A canned bubble sort animation, running on someone else's array, with someone else's variable names.

kodo

Your function, your variable names, your bug — traced step by step against the data structure it's actually built from.

how it works

Five steps, no setup.

Paste your code

Write or paste a Python solution using Kodo's starter classes (Node, Graph, etc.) — the same structures you'd already use for an array or linked-list assignment.

Guess the complexity first

Before running anything, commit to a time and space complexity guess. No peeking — this is the part most tools skip entirely.

Step through the trace

Play, pause, or step line by line. The current line highlights, and the data structure redraws itself exactly as your code would leave it at that moment.

Watch variables move with it

Every pointer and variable updates in a side panel in sync with the visual — so an index bug or a lost reference is visible the instant it happens.

Compare your guess to reality

Kodo counts the real operations from the trace and shows you the honest estimate — and how close your guess actually was.
